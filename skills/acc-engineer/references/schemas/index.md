# ACC v1 schema index

Export the authoritative Draft 2020-12 schemas with:

```bash
acc schema --output schemas
```

Do not copy or edit exported schemas inside the Skill. Validate project artifacts with `acc validate --json`; use this index only to choose the right contract.

| Artifact | Public model | Template | Critical gate |
|---|---|---|---|
| Project | `Project` | generated by `acc init` | read-only workspace, stdio, environment `base_url_ref` |
| Operation | `Operation` | `templates/operation.yaml` | GET/HEAD, origin-relative path, exact parameter mapping, real Evidence digest |
| Capability | `Capability` | `templates/capability.yaml` | bounded declarative workflow, declared policy/evals, final `emit` |
| Policy | `Policy` | `templates/policy.yaml` | evidenced scopes and tenant field, readable/denied fields, deterministic redaction |
| Eval | `Eval` | `templates/eval.yaml` | exactly one output or error expectation |
| Evidence | `Evidence` | embedded by Operation | captured locator plus lowercase `sha256:<64 hex>` digest |

`system-map.yaml`, `capability-plan.yaml`, `preflight-report.json`, and `coverage-baseline.json` are engineering planning artifacts, not ACC public Pydantic models. Do not place them in `operations/`, `capabilities/`, `policies/`, or `evals/`.

Before validation:

1. Replace every `REPLACE_WITH_...` marker from inspected evidence or user-approved design.
2. Replace `{{ CAPTURED_SHA256_DIGEST }}` only with a digest computed from captured evidence; the marker intentionally cannot pass `Operation` validation.
3. Keep credentials out of all files. `credential_ref` and `base_url_ref` contain uppercase environment-variable names only.
4. Add one positive Eval per Capability. If scopes or tenant enforcement apply, also add an Eval expecting status 401 or 403.
